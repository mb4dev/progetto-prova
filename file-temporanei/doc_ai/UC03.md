## Diagramma delle Classi

Vedi [Architettura Base](Architettura_Base.md).

### Backend
```mermaid
classDiagram
    class AvailabilityController {
        -service: BookingService
        +getAvailability(sport: string, date: Date)
    }
    AvailabilityController --|> Controller

    class BookingService {
        <<interface>>
        +getAvailableSlots(sport, date) List~Slot~
    }
    BookingService --|> Service
    
    class DefaultBookingService {
        -repo: SlotRepository
        +getAvailableSlots(sport, date) List~Slot~
    }
    DefaultBookingService --|> BookingService
    
    class SlotRepository {
        <<interface>>
        +findOccupiedAppts(sport, date)
    }
    SlotRepository --|> Repository
    
    AvailabilityController --> BookingService
    DefaultBookingService --> SlotRepository
```

## Diagramma di Sequenza

### Full Flow
```mermaid
sequenceDiagram
    autonumber
    actor User
    participant View as AvailabilityView
    participant Presenter as AvailabilityPresenter
    participant API as APIService
    participant Controller as AvailabilityController
    participant Service as BookingService
    participant Repo as SlotRepository
    participant DB as Database

    User->>View: Seleziona Sport e Data
    View->>Presenter: onChange(sport, date)
    Presenter->>API: getAvailability(sport, date)
    API->>Controller: GET /availability?sport=...
    Controller->>Service: getAvailableSlots(sport, date)
    Service->>Repo: findOccupiedAppts(sport, date)
    Repo->>DB: SELECT * FROM bookings WHERE ...
    DB-->>Repo: List<Booking>
    Repo-->>Service: List<Booking>
    Service->>Service: calculateFreeSlots()
    Service-->>Controller: List<Slot>
    Controller-->>API: JSON [slots]
    API-->>Presenter: [slots]
    Presenter->>View: displaySlots(slots)
```
